Activity type -- the shape every activity type of this register shares.

## What an activity type holds here

The meaning of one operation: its name, its definition, the standards and literature that define
it, and its illustrations (decision D3, 2026-11-05). It holds no input, output, format, tool or
deployment. Each one is a register item of this register (`gp:register`), typed
`acttype:ActivityType` and of the Activity Type Register's item class, and an OWL class:

```turtle
gpat:intersects a acttype:ActivityType , owl:Class ;
    rdfs:subClassOf geoproc:GeoprocessingActivityType ;
    rim:inRegister gp:register ;
    rim:itemClass acttype:activityTypeItemClass ;
    acttype:usedEntityType geo:Geometry ;
    acttype:associatedAgentType prov:SoftwareAgent .
```

This is the pattern of `docs/questions-for-rim-atr-maintainers.md` ("What we plan to do"). The
Implementation Profile of the operation is a different item, of a different item class, and points
here with `activityType` (`gp:activityType`, a sub-property of `rim:relatedItem`):
`rim:RegisterItemShape` allows one item class per item, so a profile cannot be its own activity type
(`docs/implementation-profile-vs-activity-type.md`).

There are 31 activity types, one per Implementation Profile. The items are generated by
`scripts/activity_types.py` from `scripts/activity-types.yaml`; the item class IRI is written from one
constant of that script, because the upstream branch `model-tweaks` renames it.

## Geoprocessing or not

18 activity types use or generate geometries. They are sub-classes of
`geoproc:GeoprocessingActivityType` and declare `geo:Geometry` as used or generated entity type, as
in the tested pattern. The other 13 work on rasters, point clouds, feature collections or bounding
boxes. GeoSPARQL has no raster class, and how a data type of `bblocks-data-types` becomes an entity
type is question 5 to the maintainers, not answered (decision D8, open). They are direct sub-classes
of `acttype:ActivityType` and declare no entity type until then.

## What is not settled here

Decision D8 is open. Nothing here says how a run of one of these operations is typed (`rdf:type` or
`prov:type`), whether `acttype:ActivityType` specialises `prov:Activity`, or how a tier-4 process type
of `bblocks-process-profiles` relates to these items.

## Validation

`shapes.shacl` adds, for every activity type: `gp:register`, a `skos:prefLabel`, a `skos:definition`,
the `owl:Class` type and a proposed addition. The Activity Type Register's shapes and
`rim:RegisterItemShape` apply through `dependsOn`. `tests/` holds one failing fixture per constraint
and a control.
